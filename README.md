# AgentQR

让电脑上的二维码，直接在电脑上处理。

AgentQR 是一个筹备中的桌面扫码开源项目，希望把手机上“长按识别二维码”的体验带到电脑：识别屏幕或图片中的二维码，查看内容，并在合适的浏览器或客户端中继续操作。

## 为什么做 AgentQR

电脑上已经显示了二维码，却还要掏出手机扫码。领取发票、打开网页、处理邮件附件时，这种跨设备切换既打断工作，也可能让下载的文件留在手机上。

AgentQR 希望连接“识别二维码”和“继续办理”这两个步骤。首个重点场景是：从电脑上的领票二维码出发，尽可能在电脑上完成发票领取和下载。

## 计划中的体验

1. 通过快捷键框选屏幕上的二维码，或导入、粘贴二维码图片。
2. 在本机识别，展示二维码内容；对于链接，明确展示目标网址和域名。
3. 由用户选择复制内容，或在浏览器及支持的客户端中打开。
4. 对需要登录的网页，优先在用户已登录的浏览器及对应配置文件中继续操作。

以上为产品方向，尚未实现；具体交互和支持范围将在验证后确定。

## 从发票领取开始

- PDF 下载地址：确认链接后，在电脑上下载发票。
- 普通领票网页：在浏览器中继续填写信息、领取和下载。
- 需要登录的页面：尝试复用目标服务在所选浏览器中的现有登录态；必要时由用户完成登录或验证码。
- 微信专用入口、小程序码等：单独验证客户端支持情况，不承诺普通浏览器可完成。
- 纯文本或发票字段：展示识别内容，不将其误判为领票入口。

识别成功不等于业务办理成功。登录态也不能替代平台要求的授权、身份验证，或恢复已经过期的二维码。

## 隐私与安全方向

- 二维码识别优先在本机完成，不将截图上传到公共解码网站。
- 打开链接前先展示内容，不自动执行二维码中的指令。
- 复用浏览器或客户端已有会话，不以导出、复制 Cookie 作为默认方案。
- 截图、发票信息和带访问凭证的链接不默认持久化，也不写入公开日志。
- 不绕过平台的登录、授权或访问限制。

## 项目状态

当前处于需求梳理与可行性验证阶段，尚无可运行版本。

计划优先探索 macOS。桌面应用、命令行工具及插件等交付形态仍待确定，技术栈尚未选定。

下一步是使用真实领票二维码验证“识别 → 打开 → 登录或授权 → 领取 → 下载”的完整链路，再确定首版范围。
